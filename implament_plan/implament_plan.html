ต่อ Frontend ↔ Backend จริง ↔ Supabase ก่อน ลบ mockData ทีหลัง

Gong เปลี่ยนลำดับจากแผนก่อนหน้า — ขอให้ ต่อสายจริงและพิสูจน์ว่าข้อมูลไหลจาก Supabase มาโชว์ในแอปได้ก่อน ค่อยไปลบ MKT33/MKT50 + mockData เป็นงานถัดไปแยกต่างหาก แผนนี้ครอบคลุมแค่ขั้นตอนต่อสายเท่านั้น

ติดอยู่ 2 จุด ที่ script ทำแทนไม่ได้ ต้อง Gong ทำเอง:
  1. division-backend/.env ยังไม่มี — ต้องเอา password จริงของ DATABASE_URL จาก Supabase Dashboard → Project Settings → Database → Connection string → Session pooler
  2. staff_users มี 0 แถว — ยังไม่มี staff account จริงเลย ต้องสร้างที่ Dashboard → Authentication → Add user (อีเมล+รหัสผ่านอะไรก็ได้ที่จะใช้ login) แล้วบอกอีเมลกลับมา ให้ Whale ผูกเข้า staff_users

ทั้งสองอย่างนี้เป็นความลับ/ต้องทำผ่าน Dashboard เอง — เขียนสคริปต์แทนไม่ได้ (ตามกติกาเดิมที่วางไว้ใน backend CLAUDE.md)

Flow ที่จะเกิดขึ้นหลังมีของ 2 อย่างข้างบน

Gong ให้ password + อีเมล staff → เขียน division-backend/.env → รัน Go API (localhost:8080) → ผูก staff_users → พลิก VITE_USE_MOCK_DATA=false → login จริง + เห็นข้อมูลจริง

ข้อควรรู้ก่อนเริ่ม

ตอนนี้ยังไม่ได้ลบอะไรใน Supabase เลย — runners table ยังมี MKT33/MKT50 เดิม 121 คน อยู่ ส่วน Baanpong 2026 (1003 คน) ยังนอนอยู่ใน registrations (ยังไม่ผ่าน assign BIB) รอบทดสอบนี้เลยจะ เห็นข้อมูล MKT33/MKT50 เดิม ไม่ใช่ Baanpong — ตรงตามที่ควรจะเป็น เพราะจุดประสงค์รอบนี้คือพิสูจน์ว่า "สายไฟ" ทำงาน (Go ↔ Postgres ↔ Auth ↔ Realtime ↔ React) ไม่ใช่พิสูจน์ว่าข้อมูล Baanpong ครบ

ขั้นตอน (ทำหลังมี 2 อย่างข้างบนแล้ว)

ขั้นทำอะไร
1เขียน division-backend/.env จาก .env.example + password จริง
2รัน go run ./cmd/api (background, port 8080) เช็คว่าขึ้นสะอาด ไม่ panic ตอนต่อ DB/JWKS
3หา user id จากอีเมลที่ Gong สร้าง (select id from auth.users where email=...) แล้ว insert เข้า staff_users
4พลิก division-frontend/.env: VITE_USE_MOCK_DATA=false
5รัน npm run dev, login ด้วย staff account จริง
6เช็ค Dashboard/Runners โชว์ข้อมูลจริงจาก Postgres (121 คนเดิม)

เลื่อนไปทำทีหลัง (ตามที่ Gong สั่ง)

  • ลบ MKT33/MKT50 ออกจาก Supabase (runners/checkpoints/race_categories)
  • ลบ runners.json + จุด hardcode MKT33/MKT50 ในโค้ด frontend (แผนเดิมที่เขียนไว้รอบก่อน ยังใช้ได้ แค่ขยับมาทำหลังรอบนี้แทน)

การตรวจ

  1. Go process ขึ้น port 8080 ไม่มี error ใน log
  2. เปิด frontend เจอหน้า login จริง (ไม่ใช่ mock ข้าม login) → login ผ่าน
  3. Dashboard/Runners โชว์ 121 คน MKT33/MKT50 (พิสูจน์ Go ↔ Postgres ทำงาน)
  4. ทด scan 1 ครั้งที่ Check-in station → เห็นแถวใหม่ใน scan_events + live_progress อัปเดตแบบ Realtime (เปิด 2 แท็บเทียบ)
  5. cd division-frontend && npm test && npm run lint && npm run build ผ่านหมด (ไม่ได้แก้โค้ด แต่เช็คว่าไม่มีอะไรพัง)

รอ Gong ส่ง password + อีเมล staff ก่อน — พร้อมเมื่อไหร่บอกได้เลย จะเริ่มขั้น 1 ทันที

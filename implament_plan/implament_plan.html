Frontend (Puttra) · Whale · 2026-08-01

รองรับจอใหญ่ 2K/4K/8K — ขยายตัวอักษร/องค์ประกอบจริงบน Dashboard + Live Monitor

รอบก่อนแก้ .app__main ไม่ให้ cap ความกว้างแล้ว (ทุกหน้าใช้พื้นที่แนวนอนเต็มจอ) แต่นั่นแค่ทำให้ layout กว้างขึ้น — ตัวอักษร/ตัวเลข/การ์ดยังคงขนาดเท่าเดิม เปิดจอ 4K/8K จริงจะเห็นตัวหนังสือเล็กจิ๋วกลางพื้นที่ว่างมหาศาล อ่านจากระยะไกล (จอทีวี/projector ให้ครอบครัวนักวิ่งดู) ไม่ได้

ยืนยัน scope กับ Gong แล้ว:

เฉพาะ Live Monitor + Dashboard (หน้าที่ใช้โชว์จอใหญ่ให้คนดูเชียร์) — หน้าอื่น (BIB/Station/Runners/Results) เป็นเครื่องมือของเจ้าหน้าที่ ไม่ optimize สำหรับจอใหญ่ และต้องการ ขยายตัวอักษร/องค์ประกอบจริง ไม่ใช่แค่ layout กว้างขึ้นเฉยๆ

วิธีทำ — font-size: max(ขนาดเดิม, ตัวเลข vw)

ใช้ max() ไม่ใช่ clamp() แบบ token เดิม เพราะต้องการให้ โตต่อเนื่องไม่มีเพดาน ตามความกว้างจอ (2K → 4K → 8K → กว้างกว่านั้นในอนาคต) พร้อมไม่เล็กกว่าขนาดปัจจุบันบนจอทำงานปกติ (laptop ~1280-1440px)

โต proportional ตามความกว้างจอเป๊ะ — จอทีวีใหญ่มักดูจากระยะไกลกว่าด้วย ขนาดปรากฏต่อสายตาใกล้เคียงกัน

ขอบเขต — ไม่แตะ class ที่ใช้ร่วมกับหน้าอื่น

dashboard.css/monitor.css มีหลาย class ใช้ร่วมข้ามหน้า (.eyebrow, .glass-panel, .btn, .page-head h1) — แก้ตรงๆ จะกระทบทุกหน้าโดยไม่ตั้งใจ แก้ด้วยการห่อ wrapper class เฉพาะหน้า (.dashboard-page, .monitor-page) แล้วเขียน CSS แบบ descendant selector สโคปเฉพาะ: 

.dashboard-page .eyebrow { font-size: max(0.68rem, 0.76vw); }

override เฉพาะภายใน section นี้ ไม่กระทบ .eyebrow ที่หน้าอื่นใช้

การตรวจสอบ

  1. เช็คที่จอปกติ (1440px) ก่อน — ต้องเหมือนเดิมเป๊ะ
  2. จำลองจอ 2560/3840/7680px ผ่าน iframe บังคับ viewport (จอเครื่องจริงกว้างสุด 1440px) เช็คว่าโตตามสัดส่วน อ่านง่ายขึ้น ไม่ overflow
  3. เช็คหน้าอื่น (BIB, Station, Runners, Results) ที่ 3840px ว่า ไม่เปลี่ยนเลย
  4. npm run test && npm run build ผ่าน

รอ Gong ตรวจก่อนเริ่มโค้ด — งานนี้มีตัวเลข scale หลายจุดที่เลือกเอง (2.1vw, 1.6vw ฯลฯ) ถ้าอยากให้โตเร็ว/ช้ากว่านี้บอกได้ก่อนเริ่ม

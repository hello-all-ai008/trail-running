Real Backend — Supabase Postgres + Go Scan API

division-backend (Korn) · Requested by Gong · Plan reviewed 2026-07-07

Why

division-frontend is fully built and demo-correct — real 121-runner dataset, gun-time ranking, scan-validation engine — but everything lives in browser localStorage. A check-in scanned at one laptop is invisible to the checkpoint/finish stations on other devices. This plan replaces that with a real Supabase Postgres DB + Go API so all scan stations share one source of truth in real time.

Schema — 6 tables

TablePurpose
race_categoriesMKT33 (start 05:30), MKT50 (start 05:00) — matches frontend
checkpointsA1/A2/A3 per category — matches frontend
runnersSeeded from runners.json, status enum REGISTERED→...→FINISHED/DNF/DNS
rfid_tagsSchema only this pass, unused until BIB/RFID phase
scan_eventsAppend-only audit log, never UPDATE/DELETE
live_progressPII-light, upserted per scan — only table open to anon + Realtime

Plus staff_users(user_id, role) driving authz. RLS: raw tables staff/admin-only; live_progress open-read; all client writes denied (Go uses service-role key).

Staff auth

Real Supabase Auth users, admin-provisioned (no public signup). Go verifies JWTs via Supabase JWKS in middleware. Frontend gets a small new LoginPage + auth guard — existing pages untouched.

Go backend layout

division-backend/
├── go.mod
├── cmd/api/main.go
├── internal/
│   ├── config/      # env vars
│   ├── db/          # pgx pool
│   ├── httpapi/     # router + middleware
│   ├── authz/       # JWT verify, role lookup
│   ├── runner/       GET /runners, /runners/:bib/report
│   ├── checkpoint/   GET /checkpoints
│   ├── scan/         POST /scan — validate/transition/log core
│   └── results/      GET /results, /stats, /results/export.csv
└── .env.example

Hand-written pgx queries this pass (no sqlc — not installed, query set small enough that codegen now is speculative). scan package ports the same rules already proven in raceEngine.js: duplicate → reject+log, checkpoint/finish before check-in → reject+log, first-scan-wins. Each scan is one transaction: validate → insert scan_events → update runners.status → upsert live_progress.

Realtime

Supabase Realtime "Postgres Changes" on live_progress, subscribed directly from React via supabase-js. No Go WebSocket hub.

Deploy division-backend (Go) ขึ้น Fly.io

Frontend ขึ้น Vercel แล้ว (https://trail-running.vercel.app) แต่ VITE_API_BASE ยังชี้ placeholder ที่ไม่มีจริง — scan/checkpoint/realtime บน production ใช้จริงไม่ได้จนกว่า backend จะ deploy ขึ้น Fly.io เสร็จ

ตรวจโค้ดแล้ว — พร้อม deploy เกือบทั้งหมด:

  • fly.toml มีอยู่แล้ว ครบ (app trail-running-api, region nrt, port 8080, health check /healthz) ไม่ต้องแก้
  • Dockerfile โครงสร้างถูก แต่ pin เวอร์ชัน Go หลวมไป (golang:1.26 vs go.mod ขอ 1.26.2) — จะ pin ให้ตรง
  • flyctl บนเครื่องนี้ตอนนี้ ใช้งานไม่ได้จริง (Homebrew โชว์ installed แต่ binary หาย) ต้อง reinstall ก่อน

ขั้นตอน

  1. Pin เวอร์ชัน Go ใน Dockerfile — FROM golang:1.26 → FROM golang:1.26.2 ให้ตรง go.mod กันบิลด์พังกลางทาง
  2. Reinstall flyctl — brew reinstall flyctl
  3. Login — fly auth login (เปิด browser ให้ Gong กดยืนยันเอง เหมือนตอน Vercel)
  4. Adopt fly.toml เดิม — fly launch --copy-config --no-deploy ใน division-backend/ สร้าง app record บน Fly โดยไม่ deploy ทันที (ปฏิเสธ Fly Postgres เพราะใช้ Supabase อยู่แล้ว)
  5. ตั้ง secrets — fly secrets set DATABASE_URL=... SUPABASE_URL=... ใช้ค่าจริงจาก division-backend/.env (Supabase project เดียวกับ frontend: emuojzwieluldwvbskxp, ap-northeast-1)
  6. Deploy — fly deploy
  7. ตรวจสุขภาพ — fly status, curl https://trail-running-api.fly.dev/healthz ต้องได้ 200
  8. ปิด loop กับ frontend — อัพเดท Vercel env VITE_API_BASE เป็น URL จริง แล้ว vercel --prod redeploy อีกครั้ง

ไฟล์ที่แตะ

ไฟล์เปลี่ยนอะไร
division-backend/Dockerfilepin เวอร์ชัน Go บรรทัดเดียว

ไม่แตะ: fly.toml, โค้ด Go อื่นทั้งหมด — เป็น deploy config ล้วนๆ ไม่ใช่ feature work

ยังไม่ทำรอบนี้

  • แก้ doc เก่าใน division-backend/CLAUDE.md (region เขียนผิดเป็น sin/ap-southeast-1 ทั้งที่ของจริงคือ nrt/ap-northeast-1) — ไม่ใช่ blocker แจ้ง Korn แก้แยกทีหลังได้
  • ยืนยัน scan จริงแบบ end-to-end — รอ Gong สร้าง staff Supabase Auth account เอง ไม่เกี่ยวกับ deploy รอบนี้

ความเสี่ยง

  • fly auth login ต้อง interactive ผ่าน Gong เอง
  • ถ้า DATABASE_URL/SUPABASE_URL ผิด แอปจะ fail health check ค้าง (fail-fast ตาม config.Load()) — เช็ค fly logs ถ้า deploy ไม่ผ่าน
  • Fly.io อาจขอ payment method ตอน launch ครั้งแรก — ให้ Gong ทำเอง

การตรวจสอบ

  1. fly status -a trail-running-api — machine running, health check ผ่าน
  2. curl -i https://trail-running-api.fly.dev/healthz → 200
  3. เปิด https://trail-running.vercel.app หลัง redeploy frontend เช็ค network reachable (auth เต็มระบบรอ staff account)

รอ Gong พิมพ์ "ลุยได้" ก่อนเริ่ม execute — ตามที่ Gong ขอไว้ จะไม่เริ่มรัน command ใดๆ จนกว่าจะได้รับคำสั่งชัดเจนอีกที แม้ตรวจแผนผ่านหน้าจอ plan mode ไปแล้วก็ตาม

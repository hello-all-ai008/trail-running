หน้า "สร้าง BIB (PDF)" แบบ Canva — ลากวางองค์ประกอบได้อิสระ

หน้า สร้าง BIB (PDF) มีอยู่แล้ว แต่ layout ตอนนี้ fix ตายตัว: แถบ header บน → เลข BIB กลาง → กล่อง checkpoint เรียงแถวนอน → แถบ footer ล่าง (BibTagPreview.jsx + BibDocument.jsx ต้อง mirror layout กันด้วยมือ 2 ไฟล์). Gong อยากได้ตัวสร้าง BIB ที่ custom เองได้แบบ Canva — อัปโหลดรูปมาวางเป็น header/footer เอง ใส่ข้อความรายละเอียดเอง ลากวางตำแหน่งอิสระ

ยืนยัน scope กับ Gong แล้ว:

ลากได้ ทุกอย่างรวมเลข BIB และกล่อง checkpoint แต่ละกล่องแยกกัน ไม่ fix แถวเหมือนเดิม — freeform เต็มรูปแบบ แลกกับความเสี่ยงลากพลาด จึงต้องมีปุ่ม "รีเซ็ตเป็นค่าเริ่มต้น" รองรับ

โครงสร้างข้อมูล — เปลี่ยนจาก headerImage/footerImage คงที่ → elements[]

Template เดียว ใช้ร่วมกันทุกระยะ (เหมือนพฤติกรรม header/footer เดิมที่เป็น global ไม่ใช่ per-category):

{
  elements: [
    { id, type: 'image',  xPct, yPct, wPct, hPct, zIndex, src },
    { id, type: 'text',   xPct, yPct, wPct, hPct, zIndex, text, fontSize, fontWeight, color, align },
    { id, type: 'bibNumber',     xPct, yPct, wPct, hPct, zIndex, fontSize, fontWeight, color, align },
    { id, type: 'checkpointBox', role: 'start'|'cp1'|'cp2'|'cp3'|'cp4'|'finish', xPct, yPct, wPct, hPct, zIndex, fontSize },
  ],
  categories: [...]  // ไม่แตะ — prefix/totalDigits/startSeq/checkpointCount เดิม
}
  • 6 checkpointBox slot คงที่เสมอ (start, cp1-4, finish) — ลากตำแหน่งแต่ละอันแยกกันได้ล่วงหน้า ตอน preview/PDF จะ render เฉพาะ role ที่ตรงกับ checkpointCount ของ category ที่เลือก (checkpointCount=2 → โชว์ start, cp1, cp2, finish ซ่อน cp3/cp4) — เลี่ยงปัญหา reconcile ตำแหน่งใหม่ทุกครั้งที่เปลี่ยนจำนวน CP
  • bibNumber มีอันเดียว — ตำแหน่ง/สไตล์ปรับได้ เนื้อหาเลขจริงมาจาก generateBibNumbers ต่อใบเหมือนเดิม
  • image/text เพิ่ม/ลบได้อิสระ — ตอบโจทย์ "อัปโหลดรูปมาใส่เป็น header/footer" และ "ข้อความใส่รายละเอียด" โดยตรง
  • Layer order = ลำดับใน array (zIndex); ปุ่ม "เอาไว้หน้า/เอาไว้หลัง" ในแผงคุณสมบัติ
  • Migration: useBibConfig.js มี migration อยู่แล้ว (migrateCategory) — เพิ่ม migration ที่ 2: config เก่าที่มี headerImage/footerImage ตรงๆ → แปลงเป็น image element ตำแหน่งบน/ล่างอัตโนมัติ + default position ให้ bibNumber/checkpointBox ตาม layout fix เดิม (ภาพเหมือนเดิมเป๊ะจนกว่าจะลากเอง) ไม่ทำให้ draft เดิมของ Gong หาย

การลาก/ปรับขนาด — ไม่เพิ่ม dependency ใหม่

พิจารณา react-rnd / react-moveable แล้ว — ตัดสินใจ เขียนเองด้วย pointer events ธรรมดา เพราะ scope แคบและชัดเจน (translate + resize มุม 4 จุด บน container สัดส่วนคงที่ตัวเดียว ไม่มี rotate ไม่มี multi-container) สั้นกว่าและไม่เพิ่ม bundle ให้หน้า admin ที่ไม่ค่อยมีใครเข้า

  • คลิก element → เลือก (โครงไฮไลต์ + handle มุมสำหรับ resize)
  • ลาก body → เปลี่ยน xPct/yPct; ลาก handle มุม → เปลี่ยน wPct/hPct
  • คำนวณ pct จาก getBoundingClientRect() ของ canvas (สัดส่วน A4 ครึ่งใบ 210:148.5 คงที่ ใช้ค่าเดียวกับ .bib-tag-preview เดิม)
  • Toolbar เหนือ canvas: + เพิ่มรูปภาพ, + เพิ่มข้อความ, รีเซ็ตเป็นค่าเริ่มต้น
  • แผงคุณสมบัติ: image → เปลี่ยนรูป/ลบ; text/bibNumber/checkpointBox → font size, weight, สี, align (text แก้เนื้อหาได้, bibNumber/checkpointBox แก้เนื้อหาไม่ได้เพราะเป็นข้อมูลจริง); ลบได้เฉพาะ image/text (bibNumber/checkpointBox ห้ามลบ — โครงสร้าง BIB ต้องมีเลข/checkpoint ครบ)

PDF Generation — ใช้ template เดียวกัน ไม่ hand-sync 2 ที่แบบเดิม

BibDocument.jsx เขียนใหม่: TagContent render จาก elements[] เดียวกับ preview แทน layout fix เดิม — ตำแหน่ง pct แปลงผ่าน helper กลางตัวเดียว (lib/bibTemplate.js) ใช้ร่วมกันทั้ง preview (HTML) และ PDF (react-pdf) แก้ปัญหาคอมเมนต์เดิมใน bib.css ที่บอกว่า hand-kept-in-sync กันเอง 2 ไฟล์

ความเสี่ยงทางเทคนิคหลัก: ต้องตรวจสอบตั้งแต่ต้นว่า react-pdf v4 รองรับ position: 'absolute' + left/top/width/height เป็น % ตามที่คาด ถ้าไม่รองรับ fallback คือแปลง pct → pt ตรงๆ (คำนวณจากขนาดพื้นที่ tag จริง) — ทำได้เหมือนกัน แค่ต้องมีขนาด canvas อ้างอิงคงที่

Layout สองใบต่อ A4 + หมุน 180° ใบล่าง (ของเดิม) ไม่แตะ

นอกขอบเขตรอบนี้

หมุน element, undo/redo, เลือกหลาย element พร้อมกัน, เส้น snap/จัดกึ่งกลางอัตโนมัติ, template แยกต่อ category (ยังใช้ร่วมกันทุกระยะเหมือนเดิม) — บอกได้ถ้าอยากได้เพิ่มทีหลัง

ความเสี่ยง

1react-pdf รองรับ % position หรือไม่ — ต้อง validate จริงตอน build มี fallback แปลง pct→pt เองไว้แล้ว

2ไม่มี component-level test infra (ไม่มี @testing-library, มีแค่ vitest สำหรับ pure function) — drag/resize ต้อง manual test ผ่าน dev server เท่านั้น ส่วน logic ล้วน (bibTemplate.js, migration) เขียน unit test ได้ตามแบบไฟล์เดิม

3Data migration — ต้องทดสอบว่า config เก่าใน localStorage (headerImage/footerImage ตรงๆ) แปลงเป็น elements ถูกต้อง ไม่ทำรูปที่ Gong อัปโหลดไว้แล้วหาย

การตรวจสอบ

  1. npm run dev (ใน division-frontend/) เปิดหน้า #/bib
  2. เพิ่มรูปภาพ ลากไปวางบน/ล่าง (จำลอง header/footer), เพิ่มข้อความ ลากวางที่ว่าง
  3. ลากเลข BIB และกล่อง checkpoint แต่ละกล่องไปคนละตำแหน่ง, resize ดูว่า handle ทำงานถูก
  4. เปลี่ยน checkpointCount ของ category แล้วเช็คว่ากล่องที่ไม่เกี่ยวข้องซ่อนถูกต้อง
  5. กด "รีเซ็ตเป็นค่าเริ่มต้น" เช็คว่ากลับไป layout fix เดิมได้
  6. กด "ดาวน์โหลด PDF" เทียบภาพใน PDF กับที่เห็นบนจอ ต้องตรงกัน
  7. Reload หน้าเว็บ เช็คว่า layout ที่จัดไว้ยังอยู่ (persist ผ่าน localStorage)
  8. ทดสอบ migration: ยัด JSON แบบเก่า (headerImage/footerImage) ใส่ localStorage มือ เช็คว่า migrate ถูกต้อง ไม่หายรูป
  9. npm run test (vitest) ผ่านหมด รวม unit test ใหม่ของ bibTemplate.js

รอ Gong ตรวจแผนนี้ก่อนเริ่มโค้ด — ตาม scope ที่ยืนยันแล้ว (ลากได้ทุกอย่างรวมเลข BIB + checkpoint แยกกล่อง) ถ้าโอเคบอกได้เลยแล้วเริ่มทำ
